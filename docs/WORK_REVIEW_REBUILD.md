# 作業レビュー画面の再構築

2026-09-12。提供された `work_analysis_specification.md`、HTML、ソースZIPを基に、既存Nodeアプリの主画面を再構築した記録。

## 画面と使い方

`npm.cmd start` で起動し、`http://127.0.0.1:4173/review.html` を開く。レビュー画面の初期表示は120分の架空サンプル。新しいUIに外部ライブラリ・ビルド・APIキーは不要。2026-09-24以降、トップの `/` は分析開始画面に進む。

1. **動画と作業区間**：対象動画を選び、対応する結果JSONを読み込む。動画を変更すると以前の結果を解除する。「動画を外す」は再生だけを解除し、表示中の結果は保持する。
2. **区間を確認**：一覧・全体時間軸から移動する。「次の未確認へ」で確認対象を巡回し、対応・境界・メモを編集する。境界を動かすと隣接区間も連続するように変わり、変更した区間は未確認に戻る。
3. **表示を切り替え**：標準との比較、山積み・ガント・バレット、実施手順書は同じ区間を集計する。チャートや表の区間から動画へ戻れる。実施順序を標準順に置き換えない。
4. **結果を保存**：JSONは両方式・原本スナップショット・修正履歴を保持する。CSVは選択中の方式を出力し、データ種別と方式を付ける。JSONの再読込で修正を復元できる。
5. **分析履歴**：既存の保存結果をレビュー用のコピーで開く。片方式だけの実行結果を開いた場合、未実行側は空表示になる。保存先サーバーの原本や既存レビューは変更しない。

実分析の実行、標準動画・GT・語彙の登録、同意確認、Stage2再実行、中止、既存レビューの保存・履歴は `/analysis.html` にある。操作手順は [既存の操作ガイド](USER_GUIDE.md) と [運用手順](FEWSHOT_OPERATIONS.md) を参照。

新画面の「見本を選ぶ」は添付モックと同じ選択確認で、正解付き見本の登録にはならない。実登録は分析・見本管理画面で行う。選択した動画を新画面から自動送信する処理はない。

## 仕様の適用関係

| 対象 | 適用と今回の実装 |
| --- | --- |
| 利用者の作業と4画面 | [添付仕様](2026-09-11_WORK_ANALYSIS_ATTACHMENT.md) のモック範囲を実装 |
| 共通の結果JSON | `schema_version: "1.0"`。[JSON例](../public/examples/work-result.json) と [Schema](work-result-schema.json) を同梱 |
| 原本とレビュー | 編集はモード別の派生データ。`original_modes` と変更前後・隣接区間の履歴を出力する。保存されたRound 18原本は変更しない |
| 推論、GT隔離、Stage1共有、Stage2時刻不変 | [Round 18仕様](2026-09-06_FEWSHOT_SPEC.md) の既存契約を継続。プロンプト本文と凍結原本を変更していない |
| 添付の180秒チャンク・前後再確認・候補検索 | 将来の実分析案。今回のモック再構築で実分析へ実装・実測済みとは扱わない |
| 添付のPython API・Cloud Run Jobs・共有DB | 将来構成。既存Nodeサーバーを維持し、Cloud Runにはデプロイしていない |
| 分割・結合・多対多の配賦 | 添付の今回範囲と同じく未実装。境界調整まで |

添付のStep2は動画・証拠パックを基本とするが、Round 18には文章照合・語彙補助・映像根拠併用の3方式がある。今回それらを同一仕様とみなして置き換えてはいない。添付内の将来の作業指示・承認記述も、今回のユーザー依頼とは区別している。

提供ZIPの元ソースは `reference/work-analysis-mock/` に保存している。実行に使う再構築版は `public/work-*.js`、`public/work-styles.css`、`public/index.html`。参照ソース用の `package.json` は、添付のCommonJSテストを既存ES Modulesプロジェクトから実行可能にするための追加ファイル。

## 既存結果からの変換

`GET /api/analysis-runs/{run_id}/work-review` を追加した。保存済み `tas-result.v1`、その実行で凍結した語彙、動画メタデータから表示用JSONへ変換する読み取り専用API。

- 対象動画の時刻、観察、根拠を引き継ぎ、標準時間は語彙の `standard_duration_s` から取得する。
- 作業ラベルは標準IDへ対応付ける。非作業ラベルだけでは標準書にないと断定できないため、対応は「要確認」にする。
- 元に存在しない方法・順序判定は未判定、活動分類も根拠がなければ判定不能として残す。人の確認状態は未確認から始める。
- `source` に元実行ID・結果ハッシュ・方式・Stage1 artifact ID・原本のURLを保持する。各区間には元の観察とラベル判定を保持する。GT作成領域は参照しない。
- TT未記録は `null` とし、80分などの値を実結果に補わない。サンプルの80分と標準時間・見本時間を混同しない。

## デザイン調査と反映

中心資料は [emilkowalski/skills](https://github.com/emilkowalski/skills)、その [Design Engineering](https://github.com/emilkowalski/skills/blob/main/skills/emil-design-eng/SKILL.md)、著者の [Agents with Taste](https://emilkowal.ski/ui/agents-with-taste)。インストールや外部スクリプト実行は行わず、設計原則を参照した。

| Before | After | 理由 |
| --- | --- | --- |
| 大きな見出し装飾・英語のキッカー・多数のカード | コンパクトな見出し、区切り線でつながる概要、動画と一覧を中心に配置 | 確認作業へ入るまでの視線移動を減らす |
| 状態色と装飾色が混在 | グラファイトのナビ、白い作業面、青の主要操作、標準対応の意味に沿った色 | 色を判断に必要な情報へ限定する |
| 太い枠や大きい角丸 | 半透明の細い境界・小さい角丸・控えめな陰影 | 作業中の情報階層を穏やかに伝える |
| 頻繁な操作も装飾的に動く | 区間選択は即時、押下140ms、ダイアログ180msのease-out | 反復操作の待ち時間を作らない |
| マウス操作中心 | フォーカス表示、キーボード操作、Escapeで閉じる、動きを減らす設定 | 使い方に応じて同じ作業を完了できる |

サーバーのCSPを緩めず、グラフの計算済み幅・位置をCSSOMから設定する。JSON内の文字列はエスケープして表示し、CSVでは数式の接頭辞を保護する。時刻・値は等幅数字にし、画面幅が狭ければ縦に並べる。
