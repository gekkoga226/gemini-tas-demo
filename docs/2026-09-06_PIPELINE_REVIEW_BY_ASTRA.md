## A. 調査サマリ

### A.1 古典的 TAS の前提と本件との差分

| 文献 | 文献上の事実 | 本件との差分 |
| --- | --- | --- |
| Abu Farha, Gall, 2019, CVPR, *MS-TCN: Multi-Stage Temporal Convolutional Network for Action Segmentation* | 時間畳み込みでフレームごとの行動を予測し、複数段で予測を洗練する。分類損失と過分割を抑える平滑化損失を使う。 | ラベル付き動画を用いて、固定されたラベル集合を学習する手法である。標準作業をプロンプトのお手本にする本件とは異なる。 |
| Li, Abu Farha, Liu, Cheng, Gall, 2020, arXiv:2006.09220, *MS-TCN++* | 初期予測と後続の洗練段階を分け、異なる範囲の時間文脈を扱う。 | 多段処理の根拠にはなるが、初段の区間を後段が変更できない本件の直列構造を支持するものではない。 |
| Yi, Wen, Jiang, 2021, BMVC / arXiv:2110.08568, *ASFormer* | 局所的な時間関係と階層的注意機構を使い、encoder の予測を decoder で洗練する。 | 小規模訓練データへの配慮はあるが、重み更新なしの in-context few-shot や文章だけの照合とは異なる。 |

**評価・提案:** 古典的 TAS と本件に共通するのは、長い動画、過分割、工程の連続性を扱う必要がある点である。一方で古典的 TAS の精度を、本件の Gemini による少数例・新規語彙・一人称組立動画の精度として扱うことはできない。

### A.2 2024年以降の VLM / LLM を使う動画理解

- **Ren, Yao, Li, Sun, Hou, 2024, CVPR, *TimeChat*** は、映像と時刻を対応づけ、長さに応じて視覚トークン数を変える動画言語モデルである。時刻付き説明、動画内の場面検索、ハイライト検出を中心に評価している。[原論文](https://openaccess.thecvf.com/content/CVPR2024/html/Ren_TimeChat_A_Time-sensitive_Multimodal_Large_Language_Model_for_Long_Video_CVPR_2024_paper.html)

- **Fateh, Ahmed, Khan, Zia, Tran, 2024初出・2026改訂, ACL 2026, arXiv:2412.02930, *TemporalVLM*** は、短い映像単位の時刻情報と動画全体の文脈を組み合わせる。製造組立動画データセット IndustryASM を提示するが、平均動画長は105秒、平均工程数は12であり、本件の20分・30〜60区間条件とは異なる。掲載された IndustryASM の TAS 比較は追加学習済み条件である。[原論文](https://arxiv.org/html/2412.02930v6)

- **Unmesh, Ramesh, Patel, Jain, Ramani, 2026, ICRA 2026 / arXiv:2602.21406, *Exploring Vision-Language Models for Open-Vocabulary Zero-Shot Action Segmentation*** は、フレームと候補ラベルの視覚・言語埋め込みの類似度を求め、時間的に整合した区間列へ変換する、追加学習不要の構成を提案する。[原論文](https://arxiv.org/html/2602.21406v1)

**評価・提案:** VLM が動画を説明できることは、工程語彙を固定できることの証明ではない。特に R6 は候補ラベルとの対応を先に作り、そこから区間を決める。本件はラベルを知らずに区間を決め、その後に文章だけで分類するため、重要な処理順序が異なる。

### A.3 Few-shot / In-context な TAS

**Lu, Elhamifar, 2025, ICCV, *Multi-Modal Few-Shot Temporal Action Segmentation*** は、少数の標準動画と行動名を使い、未学習の手順へ適応する問題を扱う。標準動画から行動の代表表現を作り、対象動画のフレームと照合する。視覚と言語の表現を分けて保持し、予測を融合する。完全ラベル、弱いラベル、ラベルなしのお手本を扱うが、モデル自体には事前訓練が必要である。[原論文](https://openaccess.thecvf.com/content/ICCV2025/html/Lu_Multi-Modal_Few-Shot_Temporal_Action_Segmentation_ICCV_2025_paper.html)

**評価・提案:** 今回確認できた中で、「ラベル付き標準作業動画をお手本にして別動画を分割・分類する」という問題設定に最も近い。ただし、照合時まで視覚情報を保持する点が現行案と決定的に異なる。現行案の「文章だけで十分」という仮定を裏づける研究ではない。

**Plini ほか, 2024初出・2026改訂, arXiv:2411.02570, *TI-PREGO*** は、一人称の手順動画から現在工程を認識する枝と、認識済みの工程列から次工程を予測する枝を組み合わせる。LLM は工程列からの予測に使われる。[原論文](https://arxiv.org/abs/2411.02570)

**未確認:** Gemini / GEAP、ラベル非依存の区間分割、標準・実作業とも自動生成文章のみで照合、という本件と同一条件を直接評価した論文は、今回の調査では確認できなかった。

### A.4 視覚的に似た工程の曖昧性を解く研究

- **Kung, Ramirez, Ha, Chen, Crandall, Tsai, 2025, ICCV, arXiv:2503.21055, *What Changed and What Could Have Changed?*** は、行動前後の状態変化と、起こり得た別の結果を表す文章を使い、動画表現を学習する。TAS、誤り検出、行動認識などで評価している。[原論文](https://arxiv.org/abs/2503.21055)

- **Lee, Elhamifar, 2025, ICCV, *Error Recognition in Procedural Videos using Generalized Task Graph*** は、正しい工程・背景を表すタスクグラフを動画へ対応づけ、工程分割と誤り検出を同時に行う。LLM の誤り説明と VLM の視覚表現も組み合わせる。[原論文](https://openaccess.thecvf.com/content/ICCV2025/html/Lee_Error_Recognition_in_Procedural_Videos_using_Generalized_Task_Graph_ICCV_2025_paper.html)

**評価・提案:** 本件の Stage1 は「ねじを締める」だけでなく、対象部品、作業位置、工具、操作、前後状態、見えなかった事項を残すべきである。ただし、記述欄を増やすだけで R9 と同じ効果が得られるとは言えない。順序制約は候補を絞る補助にはなるが、順序変更・抜け・手直しを自動修正すると実作業の異常を隠し得る。

### A.5 分割と分類を分ける構成の是非

**Ishikawa, Kasai, Aoki, Kataoka, 2021, WACV, *Alleviating Over-Segmentation Errors by Detecting Action Boundaries*** は、共通の視覚特徴から、フレーム分類と境界推定を別の枝で行い、推定境界を使って分類を洗練する。[原論文](https://openaccess.thecvf.com/content/WACV2021/html/Ishikawa_Alleviating_Over-Segmentation_Errors_by_Detecting_Action_Boundaries_WACV_2021_paper.html)

**評価・提案:** 分割と分類の役割分担には文献上の根拠がある。しかし、この研究は共通の視覚情報を使い、後から分類を修正できる。本件のように、文章だけを次段へ渡し、Stage2 が区間を変えられない不可逆な直列処理とは異なる。問うべき点は「二段階か、一段階か」ではなく、段階の間に何を残し、どこまで後から修正できるかである。

### B.1 文献と整合する点

2巡目レビューで指摘されたモード別プロンプト、標準側スキーマ、強制低確信度の区別、README の Check 2 説明は、Round 17 と README で反映済みである。本書では未修正事項として再提起しない。

### B.2 中心リスク: 文章化で識別情報が失われる

現行案の中心リスクは、Stage1 が異なる工程A・Bをともに「ドライバーでねじを締める」と書き、対象部品・位置・前後状態の差を落とすことである。その場合、Stage2 は動画を見直せず、文章と手順順序だけで選ぶことになる。

同じ短い文でも周辺記述が違えば識別できる場合はある。従って「似た文章なら必ず失敗する」とは断定しない。しかし、文章に残らなかった視覚情報を Stage2 が復元することはできない。これは設計上の推論であり、Gemini で実証済みの事実ではない。

R7 は視覚と言語を併用し、R9 は状態変化を動画表現へ学習させ、R10 は視覚情報と手順構造を組み合わせる。これらは、文章だけへ最終判断を依存させる一般的な根拠にはならない。

### B.3 現行の安全網の限界

制約7の自己申告と制約8の同着時の低確信度化は、誤りを見つけやすくする安全網として有用である。ただし、次の誤りは残る。

1. Stage1 は語彙を知らないため、業務上重要な差を見落としても記述が十分だと判断し得る。
2. Stage2 が誤った候補を一つだけ強く選んだ場合、同着にならず制約8は発動しない。
3. 標準側の記述が識別情報を欠く場合は、実作業側だけの自己申告では検出できない。
4. モデルの確信度が実際の正解確率に対応するかは未検証である。

したがって確信度分布を見るだけでは不十分である。全誤りのうち、自己申告・低確信度・受け皿のいずれかで警告できた割合と、警告されずに自動採用された誤り率を測る必要がある。

### B.4 境界の数秒ずれと工程の結合・分裂は別問題

時刻が数秒ずれることは第一目的に照らして許容できる可能性がある。一方、異なる工程A・Bを一つの区間に結合すると、一つの `job_no` では両方を表せない。一工程が複数区間へ分裂すると、出力の粒度と工程出現回数が変わる。

標準側が GT に沿った一工程の記述、実作業側が二工程を含む記述になると、同じ記述様式でも照合単位が異なる。Stage2 が時刻を変更できない現行設計では、この結合は回復不能である。

### B.5 評価上の注意

`語彙外率 = 0%` は必要条件だが、第一目的の達成判定として十分ではない。全区間を語彙内の誤った `job_no` に割り当てても0%になる。

第10章の MoC、クラス単位 IoU、類似工程サブセット精度は有効である。加えて、正解境界を与えた診断条件での区間ラベル正解率と、類似工程グループ別の混同行列を測るべきである。類似工程サブセットは連続区間だけでなく、離れた位置で反復する類似工程も対象に含める。

なお、MS-TCN 著者公式の評価コードは連続した同じラベルを一つの区間として扱う。このため、同じラベル内の余分な切れ目を測る指標を別に持つ必要がある。[公式評価コード](https://raw.githubusercontent.com/yabufarha/ms-tcn/master/eval.py)

## D. 検証ゲートへの追加提案

既存 Check 0〜6 は未実施であり、本書によって実施済みにはならない。追加ゲートは、短い動画で不成立を早期発見し、採用候補は20分動画でも確認する。

### 共通データ

推論用には標準動画・標準ラベル、実作業動画 URI、語彙、識別条件、プロンプト版を使う。採点専用には実作業 GT、類似工程グループ、判別に必要な視覚的差、映像だけで人が識別可能かの確認、通常・反復・抜け・手直し等の条件区分を持つ。

採点専用の実作業ラベルや判別理由はモデルへ渡さない。正解境界を渡すのは、原因切り分けの診断だけであり、通常精度として報告しない。

### Check 7: 正解境界でのテキスト照合成立性

**目的:** 分割誤りを除き、文章化した時点で必要な識別情報が残るかを直接測る。

**入力と処理:** 標準・実作業の両方へ正解境界だけを渡し、Stage1 に記述を作らせる。実作業の正解ラベルは渡さない。Stage2 に標準の記述・ラベルと実作業の記述を渡して固定区間を分類する。自由記述、案1の項目化記述、案2の語彙補助記述、案3の映像併用を比較する。案1・3は同一の実Stage1出力を使い、案2は別出力とする（Round 18の採用仕様に合わせて追記）。

**判定:** 区間ごとの `job_no` 正解率、工程ごとの区間正解率、類似工程グループ別混同行列、語彙外率、受け皿率、警告されない誤り率を出す。重要な類似工程で合意した基準を満たさなければ、文章のみの案を採用しない。

失敗例の一部は、人にも「文章だけ」「映像あり」で判定してもらう。人が映像なら識別でき、文章では識別できない場合は文章の情報不足を支持する。文章なら人は識別できるのに Stage2 が失敗する場合は照合側の問題を支持する。ただし、これは原因診断であり、厳密な理論上限ではない。

### Check 8: 固定区間による回復不能な誤り

**目的:** Stage2 が理想的に分類できても、Stage1 の区間のままでは第一目的を達成できない割合を測る。

**入力と処理:** 境界発見モードの出力を GT と重ねる。

**判定:** 異種 GT 工程を一つに含む結合、一工程の分裂、GT工程の欠落、内部境界の検出率・余分な境界数・秒誤差を出す。さらに、各予測区間を最も長く重なる GT ラベルで埋めた場合のフレーム正解率を出す。これは、固定区間へ一つずつラベルを付ける方式で得られる MoF の上限である。上限自体が低ければ、Stage2 の改善だけでは足りない。

既存 Check 5 は正解境界へ最も近い予測境界を探すため、余分な境界を増やした不利益を十分に測らない。本チェックの代用にはしない。

### Check 9: 通常運用での類似工程・手順変動への耐性

**目的:** お手本の効果と、標準手順への過度な依存を測る。

**入力と処理:** 通常の境界発見 Stage1 出力を固定して、同一出力へ Zero-shot / Few-shot の Stage2 を適用する。通常手順、順序変更、反復、抜け、手直しで採点する。標準セット・例示順を変える条件は別に扱う。

**判定:** 第10章の Acc、MoC、Edit、F1、クラス IoU、類似工程サブセット精度、受け皿率に加え、結合・分裂を併記する。全体平均だけでなく、重要工程と手順変動群で基準を満たすことを条件にする。標準順へ戻してしまう誤りが増える案は却下する。

### Check 10: 安全網の見逃し率と人の確認量

**目的:** 制約7・8と確信度が、誤ラベルをどれだけ確認対象へ回せるかを測る。

**入力:** Check 7・9 の全出力、GT、Stage1 の自己申告、Stage2 の確信度、強制低確信度フラグ、受け皿ラベル。

**判定指標:**

- 誤り検知率: 誤ラベルのうち、いずれかの確認対象になった割合
- 自動採用部分の誤り率: 確認対象でない区間のうち、誤ラベルだった割合
- 自動採用率と確認対象率
- 確信度帯別の実際の正解率

自己申告、同着による強制低下、通常の低確信度を別々に集計し、合算値も出す。強制低下区間を安全網の評価から除外しない。全件を低確信度や `その他` にすれば通るような判定にしない。

### Check 11: 映像併用案の追加価値と運用成立性

**目的:** 案3が文章化の損失を補い、20分動画でも成立するかを測る。

**入力と処理:** 同一の Stage1 出力を使い、次の条件を比較する。

1. 文章のみ
2. 文章＋実作業動画1本
3. 文章＋実作業動画1本＋標準区間の代表静止画列

標準代表画像には元動画ID、区間ID、元時刻を付ける。選択規則は標準側だけで決め、評価動画の正解を見て選び直さない。

**判定:** 誤りから正解へ変わった区間数、正解から誤りへ変わった区間数、類似工程群ごとの改善、時刻不変、入力区間の欠落・重複、全段階の時間・使用量・費用を記録する。画像入力や構造化出力が通っただけで精度の `PASS` にしない。

## E. 未解決として残すもの

1. 工程を区別するために必要な差が、映像・音声だけに存在するか。内部部品状態や停止原因は見えない場合がある。
2. 標準動画が何本あれば、作業者、照明、工具、製品姿勢、遮蔽の変動を吸収できるか。
3. 映像から安定して識別できるラベル粒度はどこか。複数の妥当な分割がある場合、粒度そのものの見直しが必要になる。
4. 文章照合と映像併用の費用対効果。実測前に、どこまで記述改善で足りるかは決められない。
5. 順序情報をどこまで使うか。補助には有効だが、実際の順序違反や抜けを隠してはならない。
6. 標準静止画で動き・回転方向・短い状態変化を十分に表せるか。
7. 案2でも工程結合が主要因として残る場合、分類と区間化を再結合する設計検討が必要になる。この場合は第5.8・8.3・8.5・9.1節、第10章を含む波及分析を改めて行う。
8. 合格ラインと再現性。許容する誤ラベル、確認量、改善幅は文献だけでは決められない。予備測定後に固定し、独立した動画で確認する。
