# 作業動画 × Gemini API アノテーション支援デモ 要件仕様書

- 文書種別: MVP要件仕様書
- 作成日: 2026-08-14
- 状態: Claudeレビュー反映済み（ユーザー承認待ち）
- 対象フェーズ: 要件定義

## 1. 背景

製造作業の動画を将来のTemporal Action Segmentation（時間的アクションセグメンテーション）の教師データとして利用するには、動画内の各作業について開始・終了時刻と作業内容を正しく記録する必要がある。

Geminiへ作業動画、作業標準書PDF、検証済みプロンプトを与えることで作業区間の候補を生成できるが、現在の検証では次の問題が確認されている。

- 開始・終了時刻が数秒ずれることがある。
- 一部の短い作業を見落とすことがある。
- 同じ作業が複数回登場する場合の精度は未確認である。
- 映像だけでは作業内容を判別しにくい場合、区間が抜けたり前倒しになったりすることがある。
- 検証時の精度には50%～80%程度のばらつきがある。

したがって、AIの結果をそのまま正解とせず、人が動画を確認しながら作業区間を修正・確定する仕組みが必要である。

## 2. 目的

本MVPの目的は、次の一連の操作ができるデモを実現することである。

1. 作業動画1本と作業標準書PDF1冊を入力する。
2. 検証済みプロンプトを使ってGemini解析を実行する。
3. AIが予測した作業区間を動画とタイムラインで確認する。
4. 人が開始・終了時刻、作業識別情報、見落とし・誤検出を修正する。
5. AI予測と人による確認・修正済み結果を、それぞれJSONとして出力する。

本MVPはAIの完全自動化を目的とせず、人による確認・修正を前提とする。

## 3. 想定ユーザーと利用環境

### 3.1 想定ユーザー

- 業務・AI活用側のプロジェクトオーナーまたは担当者
- ソフトウェア開発の専門知識を前提としない。
- 1回の利用につき1人が操作する。

### 3.2 利用環境

- 1人の担当者が自分のPCのWebブラウザで利用する。
- 複数人の同時利用、ユーザー登録、権限管理、案件共有は行わない。
- MVPでは、公開可能またはデモ用の非機密動画・PDFだけを扱う。
- 動画とPDFがGeminiの外部サービスへ送信されることを、解析開始前に利用者が認識できるようにする。
- 画面はWebブラウザで利用する。参照リポジトリもローカルでWeb画面を開く構成だが、公式の対応ブラウザ一覧は確認できないため、MVPではWindowsの最新版ChromeまたはEdgeを対応候補とする。

## 4. 利用シナリオ

1. 利用者がMP4動画1本とPDF1冊を選択する。
2. 画面に表示されたファイル名を確認する。
3. 利用者が「解析開始」を実行する。
4. アプリが処理段階と経過時間を表示する。
5. Geminiの結果が9.4節Aの構造・型を満たすことを確認し、9.4節Bの品質違反がある場合は該当区間へ警告を付けてAI予測を表示する。
6. 利用者が動画を再生し、タイムラインと詳細情報を照合する。
7. 利用者が区間の時刻や作業識別情報を修正し、必要に応じて区間を追加・削除する。
8. 利用者がAI予測JSONと確認・修正済みJSONを別々にダウンロードする。

## 5. MVP範囲

### 5.1 必須機能

- MP4動画1本の選択
- PDF1冊の選択
- ファイル選択ボタン
- ドラッグ＆ドロップによるファイル選択
- 選択ファイル名の表示
- Gemini解析の手動開始
- 解析中の処理段階・経過時間表示
- 解析の中止と再実行
- AI予測JSONの検証
- 動画再生
- 作業区間のタイムライン表示
- 区間詳細の表示
- 動画とタイムラインの双方向連動
- 開始・終了時刻の編集
- Job No.、標準書ページ、作業タイトルの編集
- 区間の追加・削除
- 直前1操作のUndoとRedo
- AI予測JSONのダウンロード
- 確認・修正済みJSONのダウンロード
- 入力、Gemini、JSON、保存に関するエラー表示

### 5.2 MVPで扱う単位

- 1回の解析単位は「動画1本＋その動画に対応するPDF1冊」とする。
- 同時に複数の動画や複数のPDFは扱わない。
- 1つの動画内で同じ作業が複数回登場した場合は、出現ごとに別の区間として扱う。

## 7. 入力要件

### 7.1 入力ファイル

| 種別 | 数 | MVP対応形式 | 用途 |
|---|---:|---|---|
| 作業動画 | 1本 | MP4 | 作業映像の解析・再生 |
| 作業標準書 | 1冊 | PDF | 作業番号、ページ、作業内容との対応付け |

### 7.2 入力操作

- 動画とPDFは、ファイル選択ボタンまたはドラッグ＆ドロップで指定できる。
- 選択後、解析開始前に動画名とPDF名を画面へ表示する。
- 利用者は解析開始前に、それぞれのファイルを選び直せる。
- 動画とPDFの両方が揃うまで解析開始操作を有効にしない。
- 拡張子がMP4またはPDFでない場合は、Geminiへ送信する前にエラーとする。
- 動画がブラウザで再生できない場合は、Geminiへ送信する前にエラーとする。
- PDFとして開けない場合（ファイルが破損している、暗号化されている等）は、Geminiへ送信する前にエラーとする。PDF内のテキスト抽出可否は判定に用いず、スキャン画像のみのPDFも許容する。
- 0バイトのファイルは受け付けない。

### 7.3 MVPの入力目標と事前確認

MVPの入力目標は、動画3GB以下、作業標準書PDF42ページ以下とする。検証動画は2GB以下の見込みである。

- 動画のMVP目標上限: 3GB以下
- 作業標準書PDFのMVP目標上限: 42ページ以下
- 検証に使用する代表PDF: 42ページ
- 検証動画: 2GB以下の見込み

上記はMVPとして扱いたい目標値であり、Gemini APIが受け付ける正式な上限を意味しない。設計開始前に、動画とPDFを同時に送信した場合のAPI上限、アップロード時間、失敗時の挙動を実データで確認する。

動画の最大再生時間、解像度・映像方式、PDFのファイル容量、動画のコーデックは、代表データ確認後に確定する。

## 8. Gemini解析要件

### 8.1 プロンプト

- `reference/validated_prompt.md` を検証済みプロンプトとして使用する。
- MVPではプロンプトを利用者に編集させない。
- 明確な問題が見つかった場合も、MVP内で独断変更せず、別の改善事項として記録する。

### 8.2 モデル

- 画面上ではGeminiモデルを選択させない。
- 利用候補は `gemini-3.1-pro-preview`、`gemini-3.5-flash`、`gemini-3.6-flash` とする。今後候補が追加される可能性がある。
- 初期採用モデルは、候補モデルのAPI疎通確認後に設計フェーズで決定する。
- 実際に利用可能なAPI上のモデル名は、設計開始時に確認する。
- 実際に利用可能なAPI上のモデル名に加え、API経由での動画＋PDFの同時投入可否、入力上限、アップロード方式、同期／非同期の別を設計開始前に確認する。
- モデル変更が必要な場合に備え、画面外の設定で変更可能とする。具体的な設定方法は設計フェーズで決める。

### 8.3 APIキー

- Gemini APIキーは、アプリの起動・管理担当者が画面外の安全な設定へ登録する。
- APIキーをアプリ画面から入力・表示・ダウンロードさせない。
- APIキーを動画、PDF、JSON、通常のログ、エラー詳細へ含めない。
- APIキーが未設定の場合は解析を開始せず、「管理者による設定が必要」であることを平易に表示する。

### 8.4 解析開始

- ファイルが揃っただけでは自動実行しない。
- 利用者がファイル名と外部サービス送信を確認し、「解析開始」を実行したときに処理を開始する。

### 8.5 解析中表示

- 正確な根拠を持たない進捗率は表示しない。
- 少なくとも「ファイルを準備中」「Geminiで解析中」「結果を確認中」など、現在の処理段階を表示する。
- 解析開始からの経過時間を表示する。
- 解析中であることが明確に分かる表示を行う。
- 利用者は解析中に処理を中止できる。
- 中止後も選択済み動画とPDFを保持し、再実行できる。
- 中止は画面上の待機を終了する、利用者の意図した操作であり、エラーではない。
- 中止は外部サービス（Gemini）側の処理完了や停止を保証しない。中止後に結果が届いても画面へ反映せず、破棄する。

### 8.6 再実行

- 利用者は同じ動画とPDFでAI予測を再実行できる。
- 再実行前に、現在のAI予測・修正結果が新しい成功結果で置き換わることを確認する。
- 未出力の人手修正がある場合は、その修正を失う可能性を強く警告する。
- 新しい結果が正常に取得・検証できるまで、以前の成功結果を残す。
- 再実行が失敗または中止された場合、以前の成功結果と編集状態を保持する。

## 9. JSON要件

### 9.1 JSONの種類

MVPで利用者が扱うJSONは次の2種類とする。

| 種類 | 内容 | 変更可否 |
|---|---|---|
| `prediction.json` | 9.4節Aの構造・型を満たすAI予測（Bの品質警告を含む場合がある） | 人手編集で上書きしない |
| `reviewed.json` | AI予測を元に、人が確認・修正した最終結果 | 画面の編集結果を反映する |

- Gemini生出力とアプリ用AI予測の内容が同じ配列形式で扱えるため、`raw_response.json` は利用者向け成果物にしない。
- 障害調査のために生の応答を一時的に保持する必要性や方法は、設計フェーズで検討する。
- `reviewed.json` は `prediction.json` を直接上書きせず、別の結果として作る。
- `prediction.json` はGeminiの応答値をそのまま保持し、`duration_seconds` を含め、各項目の値を再計算・改変しない。
- `reviewed.json` 単体では、どの区間が人手で追加・修正されたかを区別できない。AI予測と人手修正の区別は、`prediction.json` と `reviewed.json` のファイル分離によってのみ行う。
- AI予測の精度を区間単位で定量評価する機能はMVPの対象外とする。

### 9.2 正式なJSON形式

`prediction.json` と `reviewed.json` は、どちらも次の配列形式とする。独自のトップレベル項目やメタ情報は追加しない。

```json
[
  {
    "start_time": "00:00:00",
    "end_time": "00:00:00",
    "duration_seconds": 0,
    "job_no": "標準書記載の工程番号・Job No.（特定できない場合は '-'）",
    "page_number": "標準書の対応ページ数（例: p.1。特定できない場合は '-'）",
    "job_title": "標準書記載の作業タイトル（特定できない場合は動画から推測したタイトル）",
    "work_content": "どんな作業をしているかの具体的な説明",
    "hand_movement": "作業者の両手・片手の動きに関する詳細な説明",
    "tools_and_parts": "使用している治工具や部品の名称のリスト"
  }
]
```

### 9.3 各項目の要件

| 項目 | 形式・意味 | reviewedでの扱い |
|---|---|---|
| `start_time` | `HH:MM:SS`、1秒単位の開始時刻 | 編集可能 |
| `end_time` | `HH:MM:SS`、1秒単位の終了時刻 | 編集可能 |
| `duration_seconds` | 終了－開始の秒数を表す整数 | 画面表示とreviewedでは自動再計算、直接編集不可 |
| `job_no` | 標準書のJob No.または工程番号。不明時は `-`。複数値（例: `1590, 1600`）を許容する自由記述の文字列 | 編集可能 |
| `page_number` | 標準書の対応ページ。不明時は `-`。範囲表記（例: `p.29-p.30`）を許容する自由記述の文字列 | 編集可能 |
| `job_title` | 標準書記載の作業名。不明時は動画からの推測名 | 編集可能 |
| `work_content` | 具体的な作業内容 | MVPでは表示のみ |
| `hand_movement` | 両手・片手の動きの説明 | MVPでは表示のみ |
| `tools_and_parts` | 使用した治工具・部品を記載した文字列 | MVPでは表示のみ |

- `prediction.json` の `duration_seconds` はGeminiの応答値をそのまま保持し、再計算しない。
- `job_no` と `page_number` は自由記述の文字列とし、複数値・範囲表記について書式検証を行わない。
- 人が既存区間の時刻、Job No.、ページ番号、作業タイトルを修正しても、`work_content`、`hand_movement`、`tools_and_parts` はAI生成の値のまま残り、MVPでは人手検証の対象外とする。

### 9.4 JSON検証規則

JSON受領時の検証は、次のAとBに分けて扱う。

#### A. 受入必須の構造・型

次のいずれかに違反した場合は、`prediction.json` 全体をエラーとし、編集画面へ進ませない。

- JSON全体が配列であること。
- 各配列要素が上表の9項目を持つこと。
- `start_time` と `end_time` が `HH:MM:SS` 形式であること。

#### B. 内容の品質チェック

次の規則はGeminiが誤りやすく、人が修正する前提の品質チェックとする。違反があっても結果を破棄せず編集画面へ進み、該当区間を警告表示する。ただし、`reviewed.json` の出力時点ではAとBの全規則を満たすことを必須とする。

- 開始時刻は終了時刻より前であること。
- 区間の長さは1秒以上であること。
- `duration_seconds` は終了時刻から開始時刻を引いた整数と一致すること。
- 区間は動画の0秒より前または動画終了後に出ないこと。
- 区間同士は重複しないこと。
- 受領時に配列を開始時刻の昇順へ並べ替えて扱う。並べ替えは内容の変更にあたらず、Bのエラー扱いにはしない。

#### 共通規則

- 時刻の精度は、Geminiが1 FPSで処理する前提に合わせて1秒単位とする。
- 区間は開始時刻を含み、終了時刻を含まない半開区間 `[start_time, end_time)` とする。境界時刻ちょうどは、その時刻を開始時刻とする区間に属する。
- 前区間の終了時刻と次区間の開始時刻が同じであることは、重複とはみなさない。
- 作業区間が存在しない空白時間は許可する。
- 同じJob No.や作業名を持つ区間が複数あっても、別々の配列要素として保持する。
- 同じ作業の各出現を画面上で区別するための識別子は内部だけで使用し、正式なJSONには追加しない。

### 9.5 手動追加区間

- 手動追加区間も正式な9項目をすべて持つ。
- 利用者は開始時刻、終了時刻、Job No.、ページ番号、作業タイトルを入力・修正できる。
- 手動追加区間の必須項目は開始時刻と終了時刻のみとし、Job No.、ページ番号、作業タイトルが未入力の場合は `-` を設定する。
- MVPで編集対象外の `work_content`、`hand_movement`、`tools_and_parts` は、手動追加時に `-` を設定する。
- `duration_seconds` は自動計算する。

## 10. UI要件

### 10.1 画面構成

- 参考画像 `reference/ui_reference.png` の考え方を取り入れた1画面構成とする。
- 同じ画面内に、入力、解析状態、動画、タイムライン、区間詳細、編集操作、JSON出力を配置する。
- 基本配置は次のとおりとする。
  - 左側: 作業動画
  - 動画の下: 色分けされた作業区間タイムライン
  - 右側: 区間一覧と選択区間の詳細
- 参考画像はレイアウトと操作イメージの参考であり、Action Segmentation機能の仕様とはしない。

### 10.2 表示情報

- 動画の現在時刻と全体時間
- タイムライン上の現在位置
- 区間ごとの開始・終了時刻
- Job No.
- 標準書ページ
- 作業タイトル
- 作業内容
- 手の動き
- 治工具・部品
- 現在表示している結果がAI予測ファイルか、人手修正済みファイルかをファイル単位で識別できる状態
- 未出力の変更があるかどうか

### 10.3 操作の分かりやすさ

- 専門用語だけのエラーや案内を表示しない。
- 編集可能項目と表示のみの項目を視覚的に区別する。
- 現在選択中の区間と、動画の現在時刻に該当する区間を区別して強調する。
- 区間は互いを見分けられるよう色分けする。
- 小さい画面では必要に応じてスクロールでき、主要操作が隠れたままにならないようにする。

## 11. タイムライン編集要件

### 11.1 時刻編集

- 区間左端のドラッグで開始時刻をおおまかに変更できる。
- 区間右端のドラッグで終了時刻をおおまかに変更できる。
- 開始・終了時刻を数値で直接入力し、1秒単位の値へ確定できる。
- ドラッグ結果を数値入力欄へ、数値入力結果をタイムラインへ即時反映する。
- 区間全体のドラッグ移動は行わない。
- 編集後の区間は、9.4節の内容規則である「開始時刻が終了時刻より前」「最小長1秒以上」「既存区間と重複しない」「動画範囲内」をすべて満たす操作だけを確定できる。満たさない操作は確定させず、理由を表示する。
- 1秒単位のドラッグ操作の精度は動画の長さに依存する。動画最大時間の上限値、またはタイムラインの拡大表示機能の要否は、設計フェーズで動画長の上限確定と合わせて判断する。

### 11.2 区間追加

「区間追加」操作を実行し、開始・終了時刻と作業情報を入力して区間を追加できる。

- ボタンから追加する場合は、動画の現在時刻を開始時刻の初期値とする。
- 区間の最小長は1秒とする。
- 区間追加の必須項目は開始時刻と終了時刻のみとする。Job No.、ページ番号、作業タイトルは、未入力の場合 `-` を設定する。
- 開始時刻または終了時刻が不足している場合は、不足項目を示して追加を確定しない。
- 既存区間と重なる場合は、重なっている箇所を示して追加を確定しない。

### 11.3 区間削除

- 選択した区間を削除できる。
- 削除前に対象区間が分かる確認を表示する。
- 削除後の空白時間は許可する。

### 11.4 作業識別情報の編集

- 選択区間のJob No.、標準書ページ、作業タイトルを編集できる。
- 作業内容、手の動き、治工具・部品は表示のみとする。
- 編集内容は `reviewed.json` に反映し、`prediction.json` には反映しない。

### 11.5 Undo／Redo

- 時刻変更、作業識別情報の変更、区間追加、区間削除について、直前1操作を取り消せる。
- Undo直後に限り、その1操作をRedoできる。
- Undo後に別の編集を行った場合、それ以前のRedoはできない。
- 1操作の単位は、ドラッグ開始から指を離すまで、数値入力の確定、区間の追加、区間の削除、識別情報1項目の確定を、それぞれ1単位とする。

## 12. 動画同期要件

- 区間をクリックすると、動画をその区間の開始時刻へ移動する。
- タイムラインの任意位置をクリックすると、動画をその時刻へ移動する。
- 動画の再生・一時停止・時刻移動に合わせて、タイムライン上の現在位置を更新する。
- 動画の現在時刻に該当する区間を強調表示する。
- 動画が空白時間を再生している場合は、該当区間なしと分かるようにする。
- 秒単位の区間境界と動画の表示位置が一致することを確認できるようにする。

## 13. 保存・出力要件

### 13.1 編集状態

- 編集内容は、画面を開いている間のセッション内で保持する。
- サーバーや案件一覧へ永続保存しない。
- ブラウザを閉じる、再読み込みする、別ページへ移動するなどして未出力の修正が失われる場合は、事前に警告する。
- 永続的に残す必要がある結果は、JSONとしてダウンロードする。

### 13.2 ダウンロード

- `prediction.json` と `reviewed.json` は別々の操作でダウンロードできる。
- ダウンロード前に、どちらの結果を出力するか明確に表示する。
- `reviewed.json` の出力前にJSON検証規則を適用し、不正な場合はダウンロードさせない。

### 13.3 ファイル名

- ファイル名は、動画名、結果種別、その解析が成功した日時から自動作成し、自動生成された名前を用いる。ファイル名の変更UIは設けない。
- 例:
  - `assembly01_prediction_20260814_213000.json`
  - `assembly01_reviewed_20260814_213000.json`
- 1回の解析セッションでは成功日時を固定し、`prediction.json` と `reviewed.json` に同一の日時文字列を用いる。
- 再解析が成功した場合は、両方のファイル名に使う成功日時を新しい値へ更新する。

## 14. エラー処理

### 14.1 基本方針

- エラーは、利用者が次に何をすればよいか分かる平易な日本語で表示する。
- 必要な場合だけ「詳細」を開き、調査用情報を確認できるようにする。
- APIキー、入力文書の全文などの秘密情報を詳細表示へ含めない。
- エラー後も安全に保持できる入力・成功結果・編集状態は保持する。

### 14.2 主なエラー

| エラー | 利用者への基本案内 | 状態の扱い |
|---|---|---|
| 動画形式・再生エラー | MP4動画を選び直すよう案内 | PDFは保持 |
| PDF形式・オープンエラー | 破損または暗号化されていない、PDFとして開けるファイルを選び直すよう案内 | 動画は保持 |
| APIキー未設定 | 管理者による設定が必要と案内 | 選択ファイルを保持 |
| Gemini通信・処理失敗 | 再実行または時間を置くよう案内 | 入力と以前の成功結果を保持 |
| JSON構文不正 | 結果を読み取れないため再実行するよう案内 | 9.4節Aの違反として、不正結果を編集画面へ出さない |
| JSON項目不足・型不正 | 結果形式が不正であることを案内 | 9.4節Aの違反として、JSON全体をエラーにし、一部だけを採用しない |
| 区間重複・時刻不正・作業時間不一致 | 問題の区間と修正方法を警告表示 | 9.4節Bの違反として編集画面へ進めるが、人が修正するまで `reviewed.json` として出力しない |
| ダウンロード失敗 | 再試行するよう案内 | 編集状態を保持 |

### 14.3 不正JSONの扱い

- 9.4節Aの構造・型に違反する場合だけ、JSON全体をエラーとして扱い、編集画面へ進ませない。一部区間だけを救済して表示しない。
- 9.4節Bの内容品質に違反する場合は結果を破棄せず、該当区間を警告表示したうえで編集画面へ進め、人が修正できるようにする。
- Bの違反が残っている間は `reviewed.json` として出力させない。
- Aのエラー内容を手作業で修正することを、非エンジニアの利用者へ要求しない。

## 15. 非機能要件

### 15.1 使いやすさ

- ファイル選択からJSON出力まで、専門知識なしで操作できる。
- 主要操作には分かりやすい日本語ラベルを付ける。
- 実行中、成功、警告、エラー、未出力変更の状態を見分けられる。
- 誤って同じ操作を連続実行しないよう、処理中は不適切な操作を無効化する。

### 15.2 応答性

- ドラッグ、数値入力、区間選択、動画移動などの画面内操作は、通常のPCで利用者が待たされたと感じない速さで反映する。
- Geminiの処理時間について根拠のない完了保証を設けず、処理段階と経過時間によって待機状態を明確にする。
- Gemini解析は検証時に約300秒（約5分）かかっている。これは目安であり、MVPの目標時間・上限時間はAPIと代表データの実測結果をもとに確定する。

### 15.3 安全性・秘密情報

- MVPでは非機密のデモ資料のみを扱う。
- APIキーを画面、JSON、通常ログ、利用者向けエラーへ露出しない。
- 外部サービスへ動画とPDFを送信することを解析開始前に明示する。
- 入力ファイルの内容を、利用者が明示していない外部サービスへ送信しない。

### 15.4 データの一貫性

- AI予測と人手修正結果を混同しない。
- `prediction.json` は人手編集で変化しない。
- 不正な時刻、区間重複、動画範囲外の区間を `reviewed.json` として出力しない。
- `reviewed.json` および画面表示上の `duration_seconds` は、常に開始・終了時刻から再計算する。`prediction.json` は対象外とし、Geminiの応答値を保持する。

## 16. 将来のAction Segmentationとの境界

本MVPが担当する範囲は、動画と作業標準書をGeminiで解析し、人が作業区間を確認・修正してJSONへ出力するところまでとする。

将来は次の利用を想定する。

```text
お手本作業動画
+
人が確認・修正した reviewed.json
        ↓
Action Segmentation
        ↓
同じ作業を行う別動画を自動分割
```

ただし、次の事項は本MVPへ含めない。

- Action Segmentationへの自動受け渡し
- 学習データセットの自動作成
- 別動画への推論
- モデル学習・評価

`reviewed.json` は将来利用を意識して残すが、そのために検証済みJSON形式へ独自項目を追加しない。

- 人が既存区間の時刻や作業識別情報を修正しても、`work_content`、`hand_movement`、`tools_and_parts` はAI生成の値のまま残り、MVPでは人手検証済みとはみなさない。
- `tools_and_parts` はカンマ区切り等が想定されるが、区切り文字の統一は保証されない。将来これを構造化データとして利用する場合は、別途パース処理が必要になる。

## 17. MVP受入条件

以下は、利用者が代表的な「動画1本＋PDF1冊」を実際に操作し、OK／NGを判定できる条件である。

### 17.1 入力

- [ ] MP4動画1本とPDF1冊を、ファイル選択ボタンで指定できる。
- [ ] MP4動画とPDFを、ドラッグ＆ドロップでも指定できる。
- [ ] 選択した動画名とPDF名を解析前に確認できる。
- [ ] MP4以外の動画またはPDF以外の文書を選ぶと、解析前に分かりやすいエラーが表示される。
- [ ] 動画またはPDFが未選択の状態では解析を開始できない。
- [ ] 0バイトのファイルを選ぶと、解析前にエラーが表示され、解析を開始できない。
- [ ] 動画を選び直すと、表示されるファイル名が新しいものに更新される。
- [ ] MVP目標範囲である3GB以下のMP4動画と42ページ以下のPDFを、API事前検証済みの代表データとして解析開始できる。

### 17.2 Gemini解析

- [ ] 「解析開始」を実行するまでGemini解析が始まらない。
- [ ] 解析開始の直前に、動画とPDFが外部サービス（Gemini）へ送信されることが画面に明示される。
- [ ] 解析中に処理段階と経過時間を確認できる。
- [ ] 解析中は「解析開始」ボタンが押せない状態になり、同じ解析が二重に実行されない。
- [ ] 解析中に処理を中止でき、中止後も同じ動画とPDFで再実行できる。
- [ ] APIキーが未設定の場合、秘密情報を表示せず、管理者による設定が必要と案内される。
- [ ] 正常なGemini結果を受け取ると、JSON検証後にAI予測が表示される。
- [ ] 解析再実行前に、現在の結果が置き換わることを確認できる。
- [ ] 再実行に失敗しても、選択済み動画・PDF、以前の成功結果、編集内容が失われず、再実行できる。

### 17.3 JSON

- [ ] AI予測を、指定された9項目を持つJSON配列として確認できる。
- [ ] 形式の壊れたJSONが返った場合、一部だけを採用せず、再実行を案内するエラーになる。
- [ ] AI予測に区間の重複や `duration_seconds` の不一致が含まれていた場合、結果は破棄されず、該当区間が画面上で警告表示され、人が修正できる。
- [ ] 同じ作業が複数回登場しても、それぞれ別区間として表示・出力される。
- [ ] 画面表示と `reviewed.json` の `duration_seconds` が開始・終了時刻から自動計算され、直接編集できない一方、`prediction.json` の値はGeminiの応答から変更されない。
- [ ] 編集前に `prediction.json` をダウンロードし、区間を1件編集・1件追加・1件削除した後に再度ダウンロードすると、2つのファイルの内容が完全に一致する。
- [ ] `job_no` に `1590, 1600`、`page_number` に `p.29-p.30` のような複数値・範囲表記が含まれていても、エラーにならず表示・編集・出力できる。

### 17.4 動画とタイムライン

- [ ] 動画をWeb画面内で再生・一時停止・時刻移動できる。
- [ ] AI予測区間がタイムライン上に色分けして表示される。
- [ ] 区間をクリックすると、動画がその区間の開始時刻へ移動する。
- [ ] タイムラインの任意位置をクリックすると、動画が対応する時刻へ移動する。
- [ ] 動画再生中、タイムライン上の現在位置が更新される。
- [ ] 動画の現在時刻に該当する区間が強調表示される。
- [ ] 区間が存在しない時刻を再生中、画面に「該当する作業区間なし」と明示され、どの区間も強調表示されていない。

### 17.5 編集

- [ ] 区間左端・右端のドラッグでおおまかな時刻を変更でき、続けて数値入力で1秒単位の値へ確定できる。
- [ ] 開始・終了時刻を `HH:MM:SS` の数値入力でも変更できる。
- [ ] 区間の右端をドラッグして終了時刻を変更すると数値入力欄の値が同じ秒数に更新され、逆に数値入力欄へ値を入力して確定するとタイムライン上の区間右端が対応する位置へ移動する。
- [ ] Job No.、ページ番号、作業タイトルを変更できる。
- [ ] `work_content`、`hand_movement`、`tools_and_parts` は確認できるが編集できない。
- [ ] 「区間追加」操作から新しい区間を追加できる。
- [ ] 選択した区間を確認後に削除できる。
- [ ] 直前1回の編集をUndoでき、Undo直後にRedoできる。
- [ ] 既存区間と重なる編集を確定できず、重なり箇所を確認できる。
- [ ] 区間のない空白時間があっても保存・出力できる。
- [ ] 区間の終了時刻を開始時刻より前に移動しようとしても確定できず、理由が表示される。
- [ ] 区間の長さを1秒未満にする編集は確定できない。
- [ ] 動画の終了時刻を超える位置へ区間を移動する編集は確定できない。
- [ ] 隣接する2つの区間の境界時刻ちょうどで動画を停止したとき、強調表示される区間が1つだけである。
- [ ] 「区間追加」で開始時刻・終了時刻を入力せずに確定しようとすると、不足項目が示されて確定しない。
- [ ] 編集を1回行った後にUndoすると1回前の状態へ戻り、続けてRedoすると元の編集後の状態へ戻る。さらにUndo後に別の編集を行うとRedoが実行できない状態になる。

### 17.6 保存・出力

- [ ] `prediction.json` と `reviewed.json` を別々にダウンロードできる。
- [ ] 自動作成されたファイル名に、動画名、結果種別、その解析が成功した日時が含まれる。
- [ ] `prediction.json` と `reviewed.json` のファイル名に、同じ解析を指す同一の日時が含まれる。
- [ ] 不正な区間を含む `reviewed.json` はダウンロードできず、修正箇所が示される。
- [ ] 未出力の修正がある間、画面上にその旨の表示があり、`reviewed.json` をダウンロードすると表示が消える。
- [ ] 未出力の修正がある状態でタブを閉じるか再読み込みすると、ブラウザ標準の離脱確認が表示され、取り消すと編集内容が保持されている。

### 17.7 エラー

- [ ] 各エラー表示に、利用者が次に行う操作（例: ファイルを選び直す／再実行する／管理者へ連絡する）が1文以上で示されている。
- [ ] 必要な場合は詳細を開けるが、APIキーなどの秘密情報は表示されない。
- [ ] ダウンロードに失敗しても編集内容が失われず、再試行できる。
