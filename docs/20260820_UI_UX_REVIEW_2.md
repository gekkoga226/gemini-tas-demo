# UI/UXデザイン再レビュー(Claude) — 20分動画・多区間での実測検証

- 文書種別: レビュー記録(再レビュー)
- レビュー実施日: 2026-08-20
- レビュー対象: `public/index.html`, `public/styles.css`, `public/app.js`, `server.js`, `README.md`
- 前回レビュー: `docs/20260820_UI_UX_REVIEW.md`(同日実施、P0〜P2の7課題を指摘)
- 検証方法: 前回指摘への対応(短区間のピクセル判定化、ドラッグ通知、凡例、警告表示、リサイズ再計算)が実装済みであることをコードで確認したうえで、`node server.js` を起動し、ヘッドレスChrome(CDP経由)で実画面を操作。**ffmpegで20分00秒のダミーMP4、独自スクリプトで4ページのダミーPDFを生成**し、実際にファイル選択欄へ読み込ませた。解析APIレスポンスのみ55区間(5〜30秒混在、意図的な重複3件含む)のデータに差し替え、実測(要素幅・ドラッグハンドル数・スクロール位置など)とスクリーンショットで検証した。コード変更は行っていない(レビューのみ)。
- 想定運用条件: 実際に扱う動画は**20分程度**。

このファイルは実装を変更しない。指摘事項の記録のみを目的とする。

## 1. 結論

**次のデモに出してよいか**: 30秒サンプルの範囲では可。**20分動画を映すデモには不可**。

**直近の改善は有効だったか**: 7項目中4項目(ドラッグ限界の通知、凡例、警告のタイムライン反映、リサイズ再計算)は実測で有効と確認。1項目(短区間の番号バッジ)は部分的。**最重要の「短区間の番号消失」対応は、判定式は改善されたが目標未達**(後述)。

**最優先で次に直すべきこと**:
1. タイムラインの表示幅を広げる(現状、動画カード横に収まり最大872px固定)
2. 区間一覧の自動スクロールのバグ修正(選択行が画面外に飛ぶ)

## 2. 直近改善の検証結果

| 改善項目 | 判定 | 実測根拠 |
|---|---|---|
| ドラッグ限界の通知 | ✅ 有効 | 実マウス操作でトースト「隣の区間または動画端を越えて移動できません。」を確認。データも変化なし |
| 凡例(選択中/現在位置/要確認) | ✅ 有効 | ヒント行に表示を確認 |
| 要確認=黄色の下辺 | ✅ 有効 | 重複を含む55区間データで、タイムライン6区間・一覧6行に警告表示を確認 |
| 選択=黄緑上辺／現在位置=赤縦線 | ✅ 有効 | 5倍拡大で両立を確認 |
| ウィンドウ幅変更時の再計算 | ✅ 有効 | 幅872px→364px→334pxで再計算を確認 |
| 上部マーカー+選択/ホバー時の番号 | 🔺 部分的 | 表示自体は動作。ただし番号バッジが区間より広く隣にはみ出す(T-03) |
| 短区間判定を24pxのピクセル基準へ | ❌ 目標未達 | 判定式は正しいが、**20分では55区間中55区間(100%)が閾値未満**。30秒の区間ですら21.8pxで24pxに届かない |

判定基準をパーセントからピクセルへ変えたこと自体は正しい方向の修正。しかし**タイムラインの表示幅が最大872pxに固定**されているため、20分(1200秒)では1px=1.38秒。5秒の作業は3.6px、30秒の作業でも21.8pxにしかならず、「24px以上で番号表示」という条件をどの区間も満たせない。

結果として20分運用では、区間番号が常時表示されることが一度もなく、**ドラッグによる時刻調整も完全に使えない**(ドラッグハンドル生成数=0)。前回P0として指摘した「短区間の番号消失」は、別の形で残っている。

## 4. タイムラインの評価(要点)

- **短区間対応は不十分**: 判定基準変更は正しいが、24pxという閾値を20分動画では誰も超えられない(最長30秒区間でも21.8px)。閾値を下げる対処は不可(3.6pxの箱に番号は物理的に入らない)。**表示幅を増やすことが唯一の実効策**。
- **黄緑/赤/黄/青の同時表示は過剰ではない**: 選択(上辺)・現在位置(縦線)・警告(下辺)・通常(面)は別チャンネルに分離されており、5倍拡大で3つ同時表示を確認しても混同しない。**問題は色数ではなく、色を載せる面積(=表示幅)**。
- **「リストへ文字情報、タイムラインはバー中心」の分担は妥当**で維持すべき。ただしリスト側が55行中5行しか見えず、自動スクロールも壊れているため、リストが機能していない。

### 最小改善案(効果が出る順)
1. T-02修正(`.segment-list`に`position:relative`) — 1行で直り体感が大きく変わる
2. タイムライン全幅化 — 872px→約1500pxで1px=0.8秒、30秒区間が37pxとなり番号もハンドルも復活
3. 一覧の高さを画面連動に
4. 番号バッジをルーラー直下の吹き出しに移動
5. 1分ごとの補助目盛り追加

### 将来の完成形
全体俯瞰バー+詳細トラックの2段構成(20分の全体像と5秒区間の操作を両立)。中間段階として、詳細トラックに拡大ボタン(1x/2x/4x/8x)と横スクロールのみを付ける案でも実装コストを抑えつつ効果が出る。

## 5. 開発チームへの実装指示(優先順)

### 優先度1: 区間一覧の自動スクロール修正(T-02)
- 変更対象: `public/styles.css`(`.segment-list`定義)、必要に応じ`public/app.js`(`renderList`)
- 変更概要: `.segment-list`に`position: relative;`を追加。より確実には`selectedRow.scrollIntoView({ block: 'nearest' })`へ置換
- 実装リスク: 低。`.segment-row.warning::after`(絶対配置の下線)の基準が変わらないか確認
- 受入確認: 55区間データで、解析完了直後に区間01の行が見えている/任意の行クリック後もその行が見えている/タイムラインのバークリック時も対応行が見えている

### 優先度2: タイムラインの全幅化(T-01前半)
- 変更対象: `public/index.html`(`.workspace`内のセクション構成)、`public/styles.css`(`.workspace`のグリッド定義)
- 変更概要: タイムラインを動画カードから切り出し、左右2カラムをまたぐ独立行に配置
- 実装リスク: 中。940px以下・620px以下のレスポンシブ定義の再調整が必要
- 受入確認: 1600px幅で`#timelineSegments`の`clientWidth`が1400px以上。20分・55区間で30秒区間に番号とドラッグハンドルが表示される

### 優先度3: タイムラインの拡大とスクロール(T-01後半)
- 変更対象: `public/index.html`、`public/styles.css`、`public/app.js`(`renderTimeline`/`renderRuler`/`seek`/`beginHandleDrag`の座標計算)
- 変更概要: 拡大率(1x/2x/4x/8x)を状態に持ち、内部幅を`trackWidth×zoom`として横スクロール可能に。再生位置への自動追従、区間選択時のスクロール
- 実装リスク: 高。ドラッグ時の秒数計算とクリックシークが、スクロール量と拡大率を考慮する必要がある
- 受入確認: 4倍拡大時に5秒区間が14px以上で描画されドラッグ可能。拡大・スクロール後もクリック位置と実際のシーク時刻が一致する

### 優先度4以降: T-03(番号バッジ配置)、T-04(キーボード操作)、T-05・T-07(一覧高さ・目盛り密度)
詳細は課題一覧を参照。
