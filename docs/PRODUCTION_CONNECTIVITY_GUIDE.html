Few-shot TAS / 接続確認

本番接続の確認ガイド

Gitからアプリを取得し、Google Cloud上のGeminiに接続できるかを、合成動画だけで安全に確認するための手順です。

最初に知っておくこと

このガイドでいう「本番環境での疎通確認」は、MOCK_MODE=false で起動し、貴社のGoogle Cloudに実際に接続できるかを確かめる作業です。公開サイトへのデプロイや、実作業動画での評価は含みません。

!
実接続はまだ測定済みではありません。この手順で分かるのは「接続できたか」です。精度、処理時間、料金、運用上の権限が十分かは、別の検証が必要です。
1. 取得・起動まずローカルで画面を開く
2. 接続設定Google Cloudの情報を入れる
3. 合成動画で確認結果と履歴を確認する

「お手本あり／なし」ボタンの意味

画面のボタン分析モード分析時に使うもの
お手本と照合Few-Shot公開済み標準セットの記述。案3では標準代表画像も使います。
お手本なしで分析Zero-Shot標準セットの記述・画像を推論へ送らず、実作業動画と確認済み語彙を使います。

「分析方式（案1〜3）」は別の選択欄です。お手本の有無と分析方式は、別々に組み合わせて選べます。

始める前の準備

  • このリポジトリを読む権限とGitのURL
  • Node.js 20.11以上、FFmpeg と ffprobe
  • Google Cloudへログインするための gcloud
  • Google Cloud担当者から受け取るプロジェクトID、リージョン、一時保存バケット、モデルID
  • API呼び出しと、一時バケットの作成・読み取り・削除を行える権限
  • 接続確認用の合成動画。実作業動画は今回使いません。
i
Google Cloud担当者への依頼文「Few-shot TASの接続確認をします。ログインする利用者に、対象プロジェクトでGemini Enterprise Agent Platformを呼び出し、一時GCSオブジェクトを作成・取得・削除できる権限を付与してください。Agent Platformサービスエージェントにも一時バケットの読み取り権限が必要です。」

手順

1

アプリを取得する

PowerShellを開き、作業用フォルダーで次を実行します。GitのURLは担当者から受け取ったものに置き換えてください。

cd C:\work
git clone <担当者から受け取ったGitのURL>
cd gemini-tas-demo

すでにこのフォルダーがある場合は、cloneせずそのフォルダーを開いてください。

2

まずモック画面を開く

外部通信をしない画面確認です。ここで画面が開けば、PC上でアプリを動かす準備ができています。

$env:MOCK_MODE = "true"
npm.cmd start

ブラウザで http://127.0.0.1:4173/ を開き、右上に「LOCAL MOCK」と表示されることを確認します。

!
これは本番接続の確認ではありません。「LOCAL MOCK」はGeminiやGoogle Cloudへ接続しない試運転です。
3

モックを停止し、Google Cloudへログインする

モックを起動していたPowerShellで Ctrl + C を押して停止します。続けて次を実行します。

gcloud auth login
gcloud auth list

ブラウザが開いたら、会社から指定されたGoogleアカウントでログインします。2行目の結果で、利用するアカウントの横に * が表示されれば成功です。

ログインできない場合はGoogle Cloud担当者へ連絡してください。認証コードやアクセストークンを人に渡さないでください。

4

接続先の情報を入力する

次の CONFIRMED_... を、Google Cloud担当者から受け取った値に置き換え、PowerShellに貼り付けます。この設定はPowerShellを閉じると消えます。

$env:MOCK_MODE = "false"
$env:DATA_ROOT = "data-real"
$env:GEAP_AUTH_MODE = "gcloud"
$env:GEAP_PROJECT = "CONFIRMED_PROJECT_ID"
$env:GEAP_LOCATION = "CONFIRMED_LOCATION"
$env:GEAP_BUCKET = "CONFIRMED_TEMP_BUCKET"
$env:GEAP_STAGE1_MODEL = "CONFIRMED_GEMINI_MODEL_ID"
$env:GEAP_STAGE2_MODEL = "CONFIRMED_GEMINI_MODEL_ID"
$env:MODEL_REVISION_SCOPE = "YOUR_VALIDATION_SESSION_VERSION"
$env:GEAP_PRINCIPAL = "CONFIRMED_CALLER_IDENTITY"
$env:MAX_UPLOAD_BYTES = "2147483648"
$env:MIN_FREE_BYTES = "1073741824"
$env:GEAP_ENVIRONMENT_CONFIRMED = "true"

data-real はモックのデータと分けて結果を保存する場所です。既存の data を消したり、同じ保存先で2つのサーバーを同時に動かしたりしないでください。

5

実接続モードで起動する

続けて次を実行します。

node server.js

「Gemini TAS local app: http://127.0.0.1:4173」と表示されたら、そのURLをブラウザで開きます。「LOCAL MOCK」ではなくGoogle Cloudの接続先情報が表示されることを確認します。

起動時に設定や権限のエラーが出たら、画面操作には進まず、そのメッセージをGoogle Cloud担当者へ共有してください。トークンや動画自体は共有しません。

6

合成入力を準備し、標準セットを作って分析する

サーバーを起動したまま、別のPowerShellでリポジトリのフォルダーを開き、次を実行します。

node tools/prepare-connectivity-inputs.mjs

このコマンドは合成MP4を2本作り、同じPCのアプリに登録します。解析や外部API呼び出しは行いません。入力JSONは connectivity-inputs に作られます。既存のモック結果・標準セットはコピーしません。

  1. 画面を再読み込みし、「標準セットを作成・確認」を開きます。
  2. 「語彙・識別条件を登録」を開き、語彙JSONに connectivity-inputs/vocabulary.json、識別条件JSONに connectivity-inputs/discriminators.json を選びます。これは人工的な工程名と空の識別条件です。内容を確認し、確認者名を入力して「確認済みとして登録」を押します。
  3. 標準動画に「合成・接続確認用標準24秒」、標準GT JSONに connectivity-inputs/standard-gt.json、確認済み語彙に登録した語彙を選びます。GTは今回登録した標準動画専用です。入力準備をやり直した場合は新しい動画とGTを組で選んでください。
  4. セット名を「合成・接続確認」とします。案1の最小確認では「案2用記述も生成」「標準代表画像を生成」を外します。画面の同意欄を確認して「標準セットを生成」を押します。ここから実APIへ送信します。
  5. 「内容の確認待ち」になったら「生成した標準記述・不足申告を確認」を開きます。合成模様の動画には実作業は映っていないため、工程名の正解や精度は評価できません。不明・観察不足があっても接続失敗とは限りません。内容を確認して「内容を確認して公開」を押します。
  6. 標準セットを選び、登録済み実作業動画に「合成・接続確認用実作業30秒」を選択。「お手本と照合」と「案1：項目化した文章照合」で「解析を開始」を押します。
!
実接続モードでは合成動画でもGoogle Cloudへ送信され、料金が発生し得ます。「サンプルを設定」はモック専用のため使いません。失敗は失敗として記録され、モック成功に置き換えません。この入力は疎通専用で、精度の評価には使えません。
7

成功を判断する

次のすべてを確認できれば、今回の「接続できるか」の確認は成功です。

  • 画面が「完了」になり、候補と根拠が表示される
  • 今回の分析が完了として履歴に残る（標準セット作成は別の履歴）
  • 画面にエラーが出ない
  • 標準セット作成と分析の各履歴で、一時媒体が「削除完了」、または送信なしの実行なら「対象なし」になる
  • 履歴でモデル名を、画面上部の送信先表示でプロジェクト・リージョンを確認できる。実行時点の設定は「AI予測JSON」の execution で確認する

最後に「お手本なしで分析」（Zero-Shot）へ切り替え、「同じ区間でラベルを再判定」を実行します。お手本あり／なしの両方で完了すれば、2つのモードの接続確認ができます。

8

終了する

画面の実行が完了し、今回の各履歴の一時媒体が「削除完了」、または送信なしなら「対象なし」になったことを確認してから、PowerShellで Ctrl + C を押します。

data-real には実行履歴や結果が残ります。動画原本・送信本文・生応答も含み、Git除外対象です。別のDATA_ROOTを使う場合はリポジトリ外を選んでください。確認結果を残す必要がある間は削除せず、保管・削除は運用担当者が判断します。

よくある状況と対応

見えている状況意味次にすること
「LOCAL MOCK」と表示される外部接続はしていません手順4の MOCK_MODE=false を確認して、サーバーを再起動します。
起動時に設定不足のメッセージ接続情報が足りません表示された項目名をGoogle Cloud担当者へ連絡します。
403エラー権限が不足していますログインアカウント、API呼び出し権限、バケット権限を確認してもらいます。
「完了」と履歴が表示される分析処理が完了しました手順7の全条件とZero-Shotを確認し、日時と結果を記録します。
費用が「不明」料金表または使用量内訳が未確認接続失敗ではありません。費用判断には使わず、料金情報を担当者に確認します。

詳しい資料

技術担当者向けの設定・権限・一時媒体の回収は、リポジトリ内の FEWSHOT_OPERATIONS.md を参照してください。実接続の成功は、精度や費用の合格を意味しません。
