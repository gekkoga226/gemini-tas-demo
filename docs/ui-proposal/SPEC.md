# UI改善提案モック — 設計スペック

対象：`public/index.html` の「解析完了後の作業画面」。
レビューで挙げた課題のうち、**タイムライン中心の改善**を実際に操作できる形で提示する。

これは **提案用の独立モック** です。`public/` 配下の実アプリには一切手を触れていない。

---

## 1. 画面

`workspace.html` 1画面のみ（`index.html` はそこへリダイレクト）。
状態は `localStorage` に永続化し、リロードしても編集が残る。

```
┌ ヘッダー：タイトル / LOCAL MOCK バッジ / 未DL件数 / リセット ────────┐
├──────────────────────────────┬───────────────────────┤
│ 02 動画とタイムライン（sticky）        │ 03 区間を確認・修正（scroll）  │
│  ┌ canvas 疑似映像 ─────────┐    │  全16区間 / 修正3件           │
│  └───────────────────────┘    │  ① 部品を準備する  修正済み     │
│  ▶ ⏸ −1s +1s  00:01:35/00:10:00 │  ② 治具に部品を位置決めする     │
│  ズーム [1x][2x][4x][8x]           │  ③ ◆位置ずれを確認する         │
│                                │  …                          │
│  0:00  2:00  4:00 ▼6:00  8:00     │  ┌ 編集フォーム ─────────┐  │
│ AI │①準備│②位置決め│◆│④仮締│…    │  │ 開始 [−][00:01:35][+]   │  │
│ 修 │①準備 │②位置決め│◆│④仮締│…    │  │  AI: 00:01:38 から変更   │  │
│      ⟨⟩         ┃00:06:12         │  └───────────────────┘  │
│                                │ 04 JSON出力                  │
└──────────────────────────────┴───────────────────────┘
```

## 2. データ

- 動画長 **600秒（10分）**、**16区間**、うち **3秒・4秒・5秒の極短区間を3本**含む。
  現行UIが破綻する条件をそのまま再現し、改善案がそれを捌けることを示す。
- `SEED.ai` … AI予測（不変の原本）
- `Store.reviewed()` … 確認・修正結果（編集対象）

## 4. 状態モデル

```js
SEED.ai                    // 16区間の原本（不変）
Store.reviewed()           // 編集中の区間配列
Store.get("zoom", 1)       // 1 | 2 | 4 | 8
Store.get("selected", 0)
Store.get("time", 0)
Store.get("downloaded", false)   // 未DL判定
Store.get("undo", []) / ("redo", [])
```

## 5. 受け入れシナリオ（`scenarios.mjs` で検証）

| ID | シナリオ | 合格条件 |
|---|---|---|
| S1 | 境界リップル | 区間②③の境界をドラッグ → ②end と ③start が一致し、隙間も重複も0 |
| S2 | クランプ | 境界を隣接区間の内側まで引いても、両区間が最低1秒を保つ |
| S3 | 永続化 | 編集 → 再読込 → 変更が残る |
| S4 | Undo多段 | 3回編集 → 3回Undo で初期状態に戻る |
| S5 | 未DL件数 | 編集した区間数と「未DL修正 N件」が一致 |
| S6 | 分割 | 再生位置で分割 → 区間数+1、総時間は不変、隙間なし |
| S7 | 削除吸収 | 区間削除 → 区間数-1、総時間は不変、隙間なし |
| S8 | リセット | reset → SEED と完全一致 |
| S9 | ズーム | 8x の内部幅が 1x の8倍 |
| S10 | キーボード | 境界ハンドルに ← を送ると1秒戻る |
